# 项目规范

两个人的代码库. 规范只解决三件事: 看得懂, 改得动, 查得到.

新建文件先抄 05-template.md, 其余按需查. 全部读完约 30 分钟.

| 文件 | 内容 | 何时看 |
| --- | --- | --- |
| 01-naming.md | 命名 | 新建文件 函数 变量 |
| 02-comment.md | 注释 | 写 docstring 与行内注释 |
| 03-step.md | 步骤与失败处理 | 函数超过 20 行 |
| 04-log.md | 日志 | 加日志 排错 |
| 05-template.md | 可复制骨架 | 每次新建文件 |
| 06-map.md | 项目地图 扫描范围 | 找文件 接手模块 |

## 五条铁律

1. 标识符英文, 注释中文, 中英文之间留空格.
2. 代码与日志里的括号用 ASCII, 不用全角括号; 注释句子保留中文标点.
3. 一个函数一个职责, 步骤 3-7 个, docstring 与代码里的编号必须一致.
4. 失败只有一种写法: `raise business_error(...)`, 文案只写一次.
5. 不提交 print, 不提交注释掉的代码, 不留未说明原因的 TODO.

## 语言

- 命名: 英文, 缩写只用 01 里的白名单.
- 注释 日志 异常: 中文为主, 技术词保留英文, 如 state chunk token rerank.
- 直接写动作, 不写"进行了一个处理操作".
- 不用生僻词, 不用全角括号.
