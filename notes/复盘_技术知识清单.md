# app/rag/import_ 技术知识清单

范围：`app/rag/import_/` 下的 7 个 Python 文件，以及它们直接调用的项目内部封装。
不包含：尚未实现的 BGE-M3 向量化、Milvus 入库、主体识别具体调用，对应文件目前只是占位。
环境：Python 3.11，依赖版本以 `pyproject.toml` 为准。

## 1. 数据流与文件职责

```
entry_service.resolve_input_file
  ├─ .md  -> state.md_path, is_md_read_enabled=True
  └─ .pdf -> state.pdf_path, is_pdf_read_enabled=True
pdf_parse_service.parse_pdf_to_markdown   PDF -> MinerU -> state.md_path
enrich_markdown_images.enrich_markdown_images
                                          图片说明 + MinIO + 替换地址
split_document.split_document             md -> chunks
item_name_service / embedding_service / index_service
                                          占位，只记 warning 后返回
```

| 文件 | 职责 | 主入口 |
| --- | --- | --- |
| `entry_service.py` | 校验输入路径，按后缀分流 md 或 pdf | `resolve_input_file` |
| `pdf_parse_service.py` | 调用 MinerU 完成 PDF 解析并解压出 md | `parse_pdf_to_markdown` |
| `enrich_markdown_images.py` | 图片说明、上传 MinIO、替换正文图片地址 | `enrich_markdown_images` |
| `split_document.py` | 标题粗切、超长细切、短碎片合并、备份 chunks | `split_document` |
| `item_name_service.py` | 主体名称识别，待实现 | `recognize_and_index_item_name` |
| `embedding_service.py` | BGE-M3 向量化，待实现 | `generate_chunk_embeddings` |
| `index_service.py` | Milvus 入库，待实现 | `index_chunks` |

### 1.1 图片增强链路

1. `load_markdown`：校验 `md_path`，读正文，定位同目录的 `images/`。
2. `collect_image_refs`：遍历图片文件，用正则找正文引用，截取前后各 100 字作为上下文。
3. `describe_images`：校验视觉配置 -> 渲染提示词 -> 图片转 data URI -> POST `/chat/completions` -> 失败用文件名兜底。
4. `upload_images_to_minio`：列出旧对象 -> `fput_object` 逐张上传 -> 全部成功才删除旧对象。
5. `replace_image_refs`：用 `![说明](URL)` 替换 `![旧说明](本地路径)`，说明做换行与方括号清洗。
6. `save_enriched_md`：写到同目录的 `{stem}_new.md`，回写 `state.md_path`。

### 1.2 切分链路

1. `read_markdown`：校验路径、补标题、统一换行符。
2. `split_by_title`：逐行扫描，代码块内不认标题；开头无标题的内容归入 `前言`。
3. `split_long_chunks`：超过 600 字的切片交给 `RecursiveCharacterTextSplitter`，每片重复标题。
4. `merge_short_chunks`：同一 `parent_title` 下，至少一片短于 400，合并后不超过 1000 才合并。
5. `append_chunk_metadata`：补 `file_title`、`parent_title`、`part`。
6. `backup_chunks`：写 `{stem}_chunks.json`，失败只告警。

## 5. 外部协议

### 5.1 MinerU 批量解析

- 申请上传链接：`POST {MINERU_BASE_URL}/file-urls/batch`，请求体含 `files`、`model_version`、`extra_formats`。
- 上传 PDF：把文件二进制 `PUT` 到返回的 `file_urls[0]`，这是预签名地址，不需要再带鉴权头。
- 查询结果：`GET {MINERU_BASE_URL}/extract-results/batch/{batch_id}`，检查 `code == 0`，再读 `data.extract_result[0]`。
- 状态：`pending`、`waiting-file`、`running`、`converting` 继续轮询；`done` 取 `full_zip_url`；`failed` 终止。
- 轮询参数：超时 600 秒，间隔 3 秒；HTTP 5xx 重试，其他非 200 终止。
- 下载解压：下载 ZIP -> 删旧目录 -> 解压 -> 找同名 md；没有同名则把 `full.md` 重命名为 `{pdf_stem}.md`。
- 官方文档：<https://mineru.net/apiManage/docs>

### 5.2 OpenAI 兼容的视觉接口

- 地址：`{OPENAI_BASE_URL}/chat/completions`，鉴权头 `Authorization: Bearer {OPENAI_API_KEY}`。
- 请求体：`model` 用 `VL_MODEL`；`temperature` 取 `LLM_DEFAULT_TEMPERATURE`，缺失时兜底 0.1；`messages[0].content` 是数组，第一项 `{"type": "text", "text": prompt}`，第二项 `{"type": "image_url", "image_url": {"url": "data:image/png;base64,..."}}`。
- 项目额外传 `"enable_thinking": false`：千问系列用它关闭思考链；换其他厂商如果报 400，先删掉这个字段。
- 响应：`choices[0].message.content`，必须是非空字符串；否则本次图片说明失败，用文件名兜底。
- 关键点：图片先读 bytes -> base64 -> data URI；`temperature` 用低值让说明稳定；单张失败不拖垮整篇文档。
- 官方文档：<https://developers.openai.com/api/docs/guides/images-vision>

### 5.3 MinIO 对象存储

- 对象键：`{MINIO_IMG_DIR 去掉首尾斜杠}/{文档名}/{图片名}`。
- 访问 URL：`http(s)://{MINIO_ENDPOINT}/{MINIO_BUCKET_NAME}/{对象键}`，协议由 `MINIO_SECURE` 决定。
- 桶策略：首次创建桶时由 `app/shared/clients/minio_utils.py` 设置为公开读，否则正文里的图片 URL 打不开。
- 清理规则：本次图片全部上传成功后，才删除该文档前缀下、本次未出现的旧对象；部分失败时保留旧对象。

## 6. 重点串讲：能回答这些问题就算复习到位

1. `entry_service` 怎么区分 md 和 pdf？
   看后缀白名单，命中 `.md` 写 `is_md_read_enabled` 和 `md_path`，命中 `.pdf` 写 `is_pdf_read_enabled` 和 `pdf_path`。
2. MinerU 为什么先申请上传链接，不直接 POST 文件？
   接口返回预签名 URL，文件由客户端直接 PUT 到对象存储，解析服务只接收批次信息。
3. MinerU 轮询为什么 5xx 重试、其他状态码终止？
   5xx 是服务端临时故障，可恢复；4xx 通常是鉴权、参数或地址错误，重试没有意义。
4. 图片为什么先上传、全部成功后才删旧对象？
   先删旧对象再上传，一旦上传失败，正文里的旧地址就失效了；先上传后清理能保证任何时刻都有可用图片。
5. 图片说明为什么允许失败？
   图片说明是增强信息，不是导入主流程；失败时用文件名作为替代文本，文档仍可继续切分和入库。
6. 切长片时为什么 `chunk_size = 600 - len(title + "\n")`？
   每个子片都要重复标题作为上下文，先扣掉标题长度，才能保证加上标题后仍接近 600 字。
7. 合并短碎片为什么必须检查 `parent_title`？
   没有 `parent_title` 的片是独立标题，强行合并会把两个不同章节的内容混在一起。
8. 为什么要跟踪代码块围栏？
   Markdown 代码块里的 `# 注释` 不是标题，围栏内不能参与标题正则匹配。
9. 为什么备份失败只告警？
   `{stem}_chunks.json` 是排错用的辅助产物，不是入库必需数据，写失败不应中断整篇文档导入。
10. 替换图片地址为什么用函数而不是替换字符串？
    图片说明或 URL 里可能出现反斜杠，字符串替换会被 `re.sub` 当成 `\1` 分组引用；函数返回原样文本最安全。
